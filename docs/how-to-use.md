# How to use

exocortex の機能は、Claude Code の skill（`exoc-review` と `exoc-translate`）を通じて使います。
[`get-started.md`](./get-started.md) で SSH 接続の確立まで済んでいることが前提です。
以降の操作はすべて Mac（クライアント）側から skill 経由で完結し、Windows 機の前に戻る場面はありません。

両方の skill に共通する前提として、`ssh exocortex` が通っている必要があります。
通らない場合、skill は設定を推測して直そうとはせず、その旨を伝えて終了します。

## exoc-review

作業中のリポジトリを exocortex に送り、コードレビューを依頼します。
Claude Code に「ローカルでレビューして」「exocortex でレビュー」のように頼むと発動します。

### レビュー対象を指定する

指定がなければ、未コミットの変更（作業ツリーと `HEAD` の差分）がレビュー対象になります。

- 「main からの差分をレビューして」のように頼むと、指定したブランチ・コミットからの差分になります。
- 「ステージ済みの変更だけレビューして」のように頼むと、`git add` 済みの範囲に絞られます。

ブランチ指定とステージ済み指定は同時にできません。

### 返ってくる内容

レビューは、変更点ごとのコメントの並びで返ります。
各コメントには、指摘の深刻さ（`critical`/`major`/`minor`/`info` の 4 段階）、対象ファイル、行番号、該当箇所の引用、指摘内容が含まれます。
コメントをどう扱うか（直すか、見送るか）は利用者が判断します。

サーバー側で context を予算内に収めるため、一部のファイルが選別から漏れることがあります。
漏れが発生した場合はその旨が添えられるので、レビューが手薄になっている可能性があると分かります。

### 精度について

レビューはローカル LLM によるもので、指摘には誤りが混ざることがあります。
明らかに誤った指摘には、その根拠とともに指摘が添えられます。
lint や型検査を置き換えるものではなく、それらの手前で行う補助的なチェックとして使います。

## exoc-translate

日本語から英語、英語から日本語への翻訳を依頼します。
Claude Code に「ローカルで翻訳して」「exocortex で翻訳」のように頼むと発動します。

### 翻訳方向を指定する

翻訳方向（`ja` → `en` か `en` → `ja` か）は必須で、依頼文から明らかでなければ確認されます。
方向は推測されません。
言語を取り違えたまま訳文が返ると、それが逆方向の結果だと気付きにくいためです。

### 訳文の受け取り方

訳文はサーバー側で生成されるそばから届き、生成の途中経過が読めます。
モデルのロードに 30 秒ほどかかることがあり、その間は生存信号だけが流れて訳文はまだ届きません。

途中で失敗した場合、その時点までの訳文は不完全なものとして扱われ、そのままでは提示されません。
その旨とエラーの内容が伝えられます。

訳文はそのまま提示され、体裁の調整や訳し直しは行われません。
