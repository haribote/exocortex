## exoc-review

作業中のリポジトリを exocortex に送り、コードレビューを依頼する。
Claude Code に「ローカルでレビューして」「exocortex でレビュー」のように頼むと発動する。

### レビュー対象を指定する

指定がなければ、未コミットの変更（作業ツリーと `HEAD` の差分）がレビュー対象になる。

- 「main からの差分をレビューして」のように頼むと、指定したブランチ・コミットからの差分になる。
- 「ステージ済みの変更だけレビューして」のように頼むと、`git add` 済みの範囲に絞られる。

ブランチ指定とステージ済み指定は同時にできない。

### 返ってくる内容

レビューは、変更点ごとのコメントの並びで返る。
各コメントには、指摘の深刻さ（`critical`/`major`/`minor`/`info` の 4 段階）、対象ファイル、行番号、該当箇所の引用、指摘内容が含まれる。
コメントをどう扱うか（直すか、見送るか）は利用者が判断する。

サーバー側で context を予算内に収めるため、一部のファイルが選別から漏れることがある。
漏れが発生した場合はその旨が添えられるので、レビューが手薄になっている可能性があると分かる。

### 精度について

レビューはローカル LLM によるもので、指摘には誤りが混ざることがある。
明らかに誤った指摘には、その根拠とともに指摘が添えられる。
lint や型検査を置き換えるものではなく、それらの手前で行う補助的なチェックとして使う。

## exoc-translate

日本語から英語、英語から日本語への翻訳を依頼する。
Claude Code に「ローカルで翻訳して」「exocortex で翻訳」のように頼むと発動する。

### 翻訳方向を指定する

翻訳方向（`ja` → `en` か `en` → `ja` か）は必須で、依頼文から明らかでなければ確認される。
方向は推測されない。
言語を取り違えたまま訳文が返ると、それが逆方向の結果だと気付きにくいためである。

### 訳文の受け取り方

訳文はサーバー側で生成されるそばから届き、生成の途中経過が読める。
モデルのロードに 30 秒ほどかかることがあり、その間は生存信号だけが流れて訳文はまだ届かない。

途中で失敗した場合、その時点までの訳文は不完全なものとして扱われ、そのままでは提示されない。
その旨とエラーの内容が伝えられる。

訳文はそのまま提示され、体裁の調整や訳し直しは行われない。

## サーバーの起動・再起動・シャットダウン

`<distro>` は exocortex をセットアップに使った WSL ディストロ名に置き換える。

サーバーを Windows ごと再起動するなどして WSL の VM が停止すると、クライアントから呼んでも届かない。
そのような時は手動で exocortex を起動する。

### 起動する

```bash
# クライアント（SSH 経由）
ssh exocortex "wsl -d <distro> -- /bin/true"
```

ディストロが起動すると、`systemctl enable` した Docker が上がり、コンテナが続いて起動する。

```bash
# クライアント（SSH 経由）
ssh exocortex "wsl -d <distro> -- docker ps --format \"{{.Names}} {{.Status}}\""
```

`ai-api` と `ollama` の 2 つが並べば、クライアントから使える状態である。

### 再起動する

```bash
# クライアント（SSH 経由）
ssh exocortex "wsl -d <distro> -- bash -c 'cd ~/exocortex && docker compose restart'"
```

### シャットダウンする

```bash
# クライアント（SSH 経由）
ssh exocortex "wsl --terminate <distro>"
```

exocortex が入ったディストロだけが停止する。
